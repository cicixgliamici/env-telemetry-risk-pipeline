# Dataset Card

## Dataset Overview

The project uses a small environmental telemetry CSV for local validation and training smoke tests. It also includes a deterministic synthetic data generator for larger review-scale runs.

The dataset represents timestamped telemetry observations with environmental and operational risk indicators.

## Schema

Required columns:

| Column | Type | Meaning |
| --- | --- | --- |
| `timestamp` | datetime | observation time |
| `humidity_pct` | numeric | relative humidity percentage |
| `temperature_c` | numeric | temperature in Celsius |
| `rainfall_mm` | numeric | rainfall amount |
| `pollution_proxy` | numeric | simplified pollution exposure proxy |
| `salinity_proxy` | numeric | simplified salinity exposure proxy |
| `pressure_hpa` | numeric | atmospheric pressure |
| `vibration_mm_s` | numeric | vibration measure |
| `exposure_hours` | numeric | duration of exposure |
| `risk_level` | numeric class | supervised target |
| `failure_risk` | numeric class | downstream or comparison label excluded from features |

## Bundled Raw Dataset

Path:

```text
data/raw/raw_dataset.csv
```

Purpose:

- fast local smoke tests
- validation examples
- lightweight training runs
- stable repository fixture

Limitations:

- very small row count
- not representative of a production telemetry distribution
- not sufficient for strong model performance claims

## Synthetic Dataset

The synthetic generator creates deterministic data using:

```bash
python scripts/generate_synthetic_data.py --output data/raw/synthetic_dataset.csv --rows 250 --seed 42
```

Purpose:

- larger review-scale smoke tests
- reproducible demos
- CI validation of schema and model paths
- robustness tests without committing large data files

The generated file is ignored by git.

## Synthetic Generation Logic

Telemetry columns are sampled from bounded distributions. A simplified risk score is computed from humidity, temperature stress, rainfall, pollution, salinity, vibration, exposure, pressure deviation, and noise.

The labels are generated by quantile thresholds:

```text
risk_level = 1 if risk_score >= quantile(risk_score, 0.62) else 0
failure_risk = 1 if risk_score >= quantile(risk_score, 0.72) else 0
```

This creates a useful class mix for tests while keeping the data reproducible.

## Validation Rules

The loader validates:

- file exists
- input path is not a directory
- required columns are present
- numeric columns are coercible to numbers
- timestamp values are parseable
- target has at least two classes

## Data Leakage Notes

`failure_risk` is intentionally excluded from supervised model features. It may encode downstream knowledge or overlap with the target. Keeping it out makes evaluation more honest.

`timestamp` is also excluded from raw model features. Time can be valuable, but it should be transformed deliberately into features such as hour, season, or rolling windows rather than passed through as a raw timestamp.

## Known Data Risks

- Small raw dataset size.
- Synthetic data is not real-world evidence.
- No external provenance for the bundled example data.
- Domain thresholds are heuristic.
- No drift benchmark dataset yet.

## Recommended Improvements

- Add domain range validation for each telemetry variable.
- Add data profile reports.
- Add drift comparison between training data and new scoring data.
- Add scenario-based synthetic datasets.
- Add missingness and corrupted-row fixtures for robustness tests.
